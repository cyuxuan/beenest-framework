# 多端身份认证 SDK 设计方案

## 1. 背景与目标

当前 SSO 系统提供统一的 `/api/auth/login` 和 `/api/auth/register` 接口。随着业务发展，平台区分出了 **客户 (Customer)** 和 **飞手 (Pilot)** 两种核心角色。这两种角色在业务属性、认证方式及安全等级上存在差异：

- **客户 (Customer)**: 侧重便捷性，如手机号/验证码登录，社交登录等。
- **飞手 (Pilot)**: 侧重资质审核与安全性，可能需要执照号登录，注册需审核等。

**目标**:
设计并拆分出两套独立的 SDK (`beenest-sso-customer-sdk` 和 `beenest-sso-pilot-sdk`)，供上层业务系统（如客户端后端、飞手端后端）直接引入使用，实现：
1. **隔离性**: 不同端只能调用其对应的认证逻辑。
2. **易用性**: 提供封装好的 Java API，屏蔽 HTTP 调用细节。
3. **扩展性**: 未来针对不同端增加特定认证方式（如人脸识别）时互不影响。

---

## 2. 总体架构设计

### 2.1 模块划分

建议在 `beenest-sso` 工程下进行如下模块重构与新增：

```text
beenest-sso/
├── sso-api             # (现有) 公共 DTO, Dubbo 接口定义
├── sso-core-sdk        # (新增) SDK 核心包：包含 HTTP 工具、Token 解析、公共配置
├── sso-customer-sdk    # (新增) 客户专用 SDK：包含客户登录/注册 API、客户 Token 拦截器
├── sso-pilot-sdk       # (新增) 飞手专用 SDK：包含飞手登录/注册 API、飞手 Token 拦截器
└── sso-server          # (现有) 认证服务端：需升级以支持多端逻辑
```

### 2.2 数据模型变更

为了区分用户身份，需在 `sso_user` 表中增加 `user_type` 字段，并在注册/登录时进行校验。

**SQL 变更**:
```sql
ALTER TABLE sso_user ADD COLUMN user_type SMALLINT DEFAULT 1 COMMENT '用户类型 1:客户 2:飞手';
CREATE INDEX idx_user_type ON sso_user(user_type);
```

## 3. SDK 详细设计

### 3.1 核心依赖 (sso-core-sdk)

该模块作为基础依赖，不直接暴露给业务方使用，主要负责：
- 封装 `OkHttp` 或 `RestTemplate` 用于请求 SSO Server。
- 定义通用的 `SsoClient` 抽象类。
- 提供 JWT Token 的本地解析与验签工具 (`JwtUtils`)。
- 定义通用配置属性类 (`SsoProperties`)。

### 3.2 客户认证 SDK (sso-customer-sdk)

**定位**: 供 "C端应用后端" 或 "Web 前台" 引入。

**功能特性**:
1. **注册**: 默认 `user_type = 1`。
2. **登录**: 支持 账号/密码、手机号/验证码。
3. **鉴权**: 提供 Spring MVC 拦截器 `CustomerAuthInterceptor`，仅允许 `user_type = 1` 的 Token 通过。

**API 设计 (Java)**:
```java
public interface CustomerAuthClient {
    /**
     * 客户注册
     */
    Response<Void> register(CustomerRegisterReq req);

    /**
     * 客户登录
     */
    Response<LoginResult> login(CustomerLoginReq req);

    /**
     * 校验 Token (远程或本地)
     */
    SsoResult<Boolean> verify(String token);
}
```

**配置项 (`application.yml`)**:
```yaml
beenest:
  sso:
    customer:
      server-url: http://sso-server:8080
      app-id: customer-app-01
```

### 3.3 飞手认证 SDK (sso-pilot-sdk)

**定位**: 供 "飞手App后端" 或 "运营平台" 引入。

**功能特性**:
1. **注册**: 默认 `user_type = 2`。
   - 包含额外字段：`license_no` (执照编号), `real_name` (真实姓名)。
   - 注册后状态可能默认为 `0` (待审核)，需人工或自动审核后开启。
2. **登录**: 支持 账号/密码、执照号/密码。
3. **鉴权**: 提供 Spring MVC 拦截器 `PilotAuthInterceptor`，仅允许 `user_type = 2` 的 Token 通过。

**API 设计 (Java)**:
```java
public interface PilotAuthClient {
    /**
     * 飞手注册 (含资质信息)
     */
    Response<Void> register(PilotRegisterReq req);

    /**
     * 飞手登录
     */
    Response<LoginResult> login(PilotLoginReq req);
    
    // ... verify
}
```

## 4. 服务端 (sso-server) 改造方案

### 4.1 接口升级

保持现有接口路径不变，或新增专用路径，建议通过参数区分：

**注册接口**: `/api/auth/register`
- 新增参数 `user_type` (必填)。
- 逻辑：根据 `user_type` 选择不同的校验策略（Strategy Pattern）。
    - Type=1: 校验手机号。
    - Type=2: 校验执照号，设置 status=0。

**登录接口**: `/api/auth/login`
- 新增参数 `user_type` (可选，若不传则查全表，若传则校验类型)。
- 逻辑：登录成功后，生成的 JWT Token payload 中必须包含 `user_type`。

### 4.2 认证策略模式

```java
public interface AuthStrategy {
    void register(RegisterDTO dto);
    LoginResultDTO login(LoginDTO dto);
    UserTypeEnum getSupportedType();
}

@Service
public class CustomerAuthStrategy implements AuthStrategy { ... }

@Service
public class PilotAuthStrategy implements AuthStrategy { ... }
```

## 5. 接入流程示例

### 5.1 客户系统接入

1. **引入依赖**:
   ```xml
   <dependency>
       <groupId>club.beenest</groupId>
       <artifactId>sso-customer-sdk</artifactId>
       <version>1.0.0</version>
   </dependency>
   ```

2. **配置**:
   ```yaml
   beenest.sso.customer.server-url=http://localhost:8080
   ```

3. **代码调用**:
   ```java
   @Autowired
   private CustomerAuthClient authClient;

   public void signUp(UserForm form) {
       authClient.register(convert(form));
   }
   ```

### 5.2 飞手系统接入

同上，引入 `sso-pilot-sdk`，调用 `PilotAuthClient`。

## 6. 安全性考虑

1. **Token 隔离**: 即使 Key 相同，Customer SDK 的拦截器也应拒绝 Pilot 的 Token (通过检查 Payload 中的 role/type)。
2. **敏感数据**: 飞手执照等信息需加密存储。
3. **接口限流**: 针对 Login/Register 接口在 Gateway 层或 SDK 层做限流保护。
